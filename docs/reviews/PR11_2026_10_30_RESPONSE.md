# Response to the second review of pull request 11 (Argon, 2026-10-30)

Review: `PR11_2026_10_30_ARGON_ICAP_ENGINE.md` (output of `tools/review/consult_argon.py`, brief
`tools/review/briefs/PR11_ICAP_ENGINE_SLICE1.md`, reviewed commit d321bce). Verdict: DO NOT MERGE, with four P0 findings.
Every finding is answered by ID below; "fixed" means fixed in pull request 11 and proved by the test named here (tests are
in `IcapEngineEndToEndTest`, `IcapParsingTest`, `DetectorSetTest`, `FenceSelfTest` and `ProductFencesTest`). The review
is evidence (AGENTS.md section 1 item 6); the corrections follow the FROZEN ICAP spec and ADR-010, so none needed a PO
decision.

| Id | Answer |
|---|---|
| D-01 (P0) | **Fixed.** Every detector stops at `MAX_FINDINGS` and nothing is truncated; reaching the limit is `UNINSPECTABLE(FINDING_LIMIT)`, which blocks on the fail-closed flow instead of redacting part of the body. Tests: `findingLimitBlocksInsteadOfPartiallyRedacting`, `findingLimitIsReported`. |
| D-02 (P0) | **Fixed.** Form-encoded bodies are percent-decoded and scanned (not rewritable, so a finding blocks). Bodies with a compression, archive or PDF signature, text that is not valid UTF-8, `multipart/*` and any media type the engine cannot read are `UNINSPECTABLE` (`BINARY`, `MULTIPART`, `UNSUPPORTED_MEDIA`) and block on the fail-closed flow until the file pipeline and decompression land. Tests: `formEncodedIdentifierIsBlocked`, `unreadableBodiesAreUninspectable`. The review's question to the PO (treat these bodies as uninspectable now) is answered by ADR-010 and SR-DLP-1 as frozen: yes, now. |
| D-03 (P0) | **Fixed.** An encapsulated HTTP head with a repeated `Content-Length`, `Transfer-Encoding`, `Content-Type`, `Content-Encoding` or `Host`, or with both `Content-Length` and `Transfer-Encoding`, is `MALFORMED` under the flow rule on REQMOD (403 on the fail-closed flow, connection closed) and 400 on RESPMOD. Every comma-separated `Content-Encoding` token other than `identity` makes the body `UNINSPECTABLE(ENCODED)`. Tests: `duplicateFramingHeadersAreMalformed`, `stackedContentEncodingIsUninspectable`. |
| D-04 (P0) | **Fixed.** The JSON scanner parses numbers by the strict RFC 8259 grammar and returns them as leaves, so an unquoted identifier is scanned and redacted (the number becomes the class-token string). Tests: `identifierAsJsonNumberIsRedacted`; the fuzz target now accepts number leaves in its span check. |
| D-05 (P1) | **Fixed.** The card detector takes the longest Luhn-valid candidate of 13 to 19 digits that ends on a boundary, so expiry or CVV groups after the number no longer hide it; the IBAN prefix is case-insensitive. Test: `cardFollowedByExpiryAndLowercaseIban`. |
| D-06 (P1) | **Fixed.** The overlap between stream windows is kept in normalised characters, so format characters cannot push a split value out of it; windows are cut on UTF-8 character boundaries (a second defect the new test exposed: a split multi-byte character decoded to U+FFFD and broke the digit run). A non-writable channel pauses reading until it drains, so a slow reader does not grow the outbound buffer. Test: `valueSplitAcrossWindowsWithFormatPaddingIsCaught`. |
| D-07 (P1) | **Fixed.** The upgrade check reads the exact status-code token, before the null-body branch, so a `101` is recorded as `WEBSOCKET_INVISIBLE_AFTER_UPGRADE` and a reason phrase containing "101" is inspected. In a previewed response, a class whose action is BLOCK replaces the whole body with the termination text; only REDACT classes are rewritten in place. Tests: `reasonPhraseContaining101IsNotAnUpgrade`, `secretInAPreviewedJsonResponseReplacesTheWholeBody`. |
| D-08 (P1) | **Fixed.** 204 is sent only before any `100 Continue`, inside a preview or with `Allow: 204`. An unchanged answer otherwise echoes the body with `Content-Length` set to the echoed length and no `Transfer-Encoding`; a body the engine did not keep in full is never echoed (500 and close). The timeout and internal-error paths follow the same rule. Tests: `allowWithout204PermissionEchoesWithCorrectLength`, `no204AfterContinueWithoutAllow`. |
| D-09 (P1) | **Fixed.** Only SP and HTAB are trimmed; a control character in a chunk-size line or a header value is refused; `Preview` with `null-body` is refused; `Encapsulated` sections must follow the RFC 3507 order. Test: `controlCharactersAndOrderingAreRefused`. |
| D-10 (P1) | **Fixed.** A transaction deadline starts with its first byte (10 s for REQMOD head and body, 300 s for RESPMOD) and the reader-idle timeout applies to a partial head as well; the receive buffer is capped at one body plus 64 KiB; an abort before the proxy finished sending closes the connection; an unreadable encapsulated head on REQMOD is a `MALFORMED` verdict with its event. Tests: `stalledHeadIsClosed`, `abortMidStreamClosesTheConnection`, `duplicateFramingHeadersAreMalformed`, `slowBodyTimesOut`. |
| D-11 (P1) | **Fixed in part.** (1) New fence `contentPackagesDoNotLog` covers `io.rwsafe.detect`, `dataplane.icap`, `dataplane.inspect` and `dataplane.server` whatever their annotations; `HeaderBlock` is `@BodyBearing` with `@BodyContent` accessors and a `toString` that reads no field. (2) The request-thread fence now also catches Netty `Future.sync/await/get` (fixture `NettyFutureSyncInspector`). (3) `ProductFencesTest` applies every product rule with `allowEmptyShould(false)`. **Kept:** the factory methods still allow empty rules, because `FenceSelfTest` evaluates each rule on single fixture classes where an empty match is the expected compliant case. `JsonLeafScanner` is covered by the package fence rather than the annotation, since it exposes no content accessor of its own. Tests: `contentPackagesDoNotLogFence`, `requestThreadFence`, `ProductFencesTest`. |
| D-12 (P2) | **Fixed in part.** `VerdictEvent.toString` prints neither the identity claim nor the client address, and both are bounded before they travel; the control plane masks the address and pseudonymises the claim before persistence (ingestion contract). An absolute request target's authority wins over `Host`, and a trailing root dot is ignored. Normalisation that expands beyond 4× the input is `UNINSPECTABLE(NORMALISATION)`. `STREAM_ABORTED` events carry the bytes forwarded before the abort in `bodyBytes`. Tests: `absoluteTargetWinsOverHost`, `eventToStringHidesIdentity`. |
