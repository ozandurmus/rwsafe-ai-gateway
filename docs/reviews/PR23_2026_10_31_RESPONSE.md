| Id | Answer |
|---|---|
| D-10 (P1) | **Fixed.** The sender keeps a delivered batch until its watermark is saved. A failed save is retried on its own, with the same exponential back-off, and the batch is not sent again. The in-memory cursor (`delivered`, which the backlog count also uses) moves only after the save succeeds. The sender's failure state then clears, so Health cannot stay `DEGRADED` after PostgreSQL recovers. Test: `SiemExporterTest.aFailedWatermarkSaveKeepsTheBatchAndRetriesTheSaveAlone` (the watermark table is renamed away and back: the cursor stays, the delivery count does not grow while the save fails, each event arrives once, and the watermark reaches the last event). |
| D-11 (P1) | **Fixed as decided (Q-SIEM-3).** (a) The backlog is counted with the same visibility barrier as the reads (`SiemExportStore.Backlog(visible, held)`, one statement per stream). Rows held behind an open transaction have their own gauge (`rwsafe_siem_backlog_held_rows`, Health). A backlog that has not moved the watermark for 3 minutes (`SiemExportService.STALL_AFTER`, above the 2-minute back-off ceiling) marks the export stalled: Health `DEGRADED` with the held count, and `rwsafe_siem_stalled`. (b) `readOnce` returns `MORE`, `CAUGHT_UP` or `DEFERRED`. Only a caught-up round recounts at once; a deferred round (full queue) is held to the 30 s interval, so an outage cannot cause a count per poll. Q-SIEM-3: `rwsafe-roles.sql` sets `idle_in_transaction_session_timeout = '60s'` for `rwsafe_app` and `rwsafe_migrate`; this is documented in LOCAL_RUN.md "SIEM export". Tests: `SiemExporterTest.rowsHeldBehindAnOpenTransactionAreCountedAndAStallIsShown` (an open transaction holds two rows: held count, stall, nothing exported, then recovery after rollback); `SiemExportStoreTest.anOlderTransactionThatCommitsLastIsNeverOvertaken` (backlog 0 visible, 2 held); `TwoRoleMigrationTest` (both roles read `1min`). |
| D-12 (P2) | **Fixed.** (a) Possibly-lost counting is once per connection and cannot miss the first batch. After the flush the sender sets `acknowledged` and then reads `peerClosed`; the watcher sets `peerClosed` and then reads `acknowledged`. Both are volatile, so at least one side sees the other and counts, and an `AtomicBoolean` keeps the count to one. This is the same guarantee as setting the flag before the flush, without counting a batch whose flush failed (that batch is retried, not lost). A write error on a connection that had acknowledged batches also counts once. (b) `connection` is volatile. `close()` sets a shutdown flag, and a connection opened by a `deliver` racing a stop is closed at once, so no socket or watcher is left behind. (c) A failed write is classified (`TIMEOUT` or `IO`) and the watchdog cancelled before the connection is closed. After a write error or a peer close only the TCP socket is closed; `close_notify` is sent only on a graceful close. Tests: `SiemTransportTest.aClosedConnectionIsDetectedAndReplacedBeforeTheNextBatch` (one batch counted once), `aReceiverThatStopsDrainingTimesOutInsteadOfHangingTheSender` (still `TIMEOUT`). |
| D-13 (P2) | **Fixed.** A vocabulary value (reason, platform, surface, step, a non-UUID correlation id) must also pass the Tier-1 detector scan and hold no run of 7 or more digits. The digit rule covers phone, account and customer numbers that no detector knows. A `system:` actor holding an estate term is withheld; a HEC index holding an estate term refuses that destination. Tests: `SiemSchemaTest.vocabularyValuesCannotCarryIdentifiersOrSecrets` (TCKN, unspaced IBAN, digits-only phone with and without a prefix, access-key and token shapes, all built at runtime, and an estate term in a `system:` actor); `SiemTransportTest.withoutThePrivacyKeyOrTheDictionaryNoExporterStarts` (HEC index). |
| Q-SIEM-3 | **Accepted as recommended:** see D-11. Superuser sessions are not covered by the role setting; that is documented. |
