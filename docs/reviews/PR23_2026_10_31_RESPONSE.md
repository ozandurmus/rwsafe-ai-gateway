| D-1 (P0) | **Fixed.** The time-based settle window is gone. V7 adds `tx_id xid8 NOT NULL DEFAULT pg_current_xact_id()` to `verdict_event` and `audit_event`, with (tx_id, id) indexes. `SiemExportStore` reads only rows with `tx_id < pg_snapshot_xmin(pg_current_snapshot())`, in (tx_id, id) order, in one statement per read. The watermark is (tx_id, id) per stream (`siem_watermark.verdict_tx_id/verdict_event_id`, `audit_tx_id/audit_id`). The migration and the store explain why no row can appear behind the cursor: every transaction below the xmin has ended, every other gets an id at or above it, and the xmin never moves back. A long transaction pauses the export and shows as backlog; it never causes a skip. Tests: `SiemExportStoreTest.anOlderTransactionThatCommitsLastIsNeverOvertaken` (two JDBC connections; the older transaction commits last, for both a verdict event and a ledger row whose audit_id is the higher one) and `verdictEventsAreReadInCommitSafeOrderAfterTheWatermarkWithTheirFindings`. |
| D-2 (P1) | **Fixed.** (a) Row keys leave as written only for allow-listed audited tables (`login_record`, `policy_snapshot`: a number; `policy_rule_version`, `policy_approval`: the V2 key shapes; `siem_watermark`: the destination). They also need no Tier-1 detector hit and no estate term. `local_account` keys become the account's `USR-` pseudonym; any other key, of any table, becomes a keyed `KEY-` token under rwsafe's HMAC key (the funnel's layer 4). A key that cannot be pseudonymised is `[WITHHELD]`. (b) Every verdict and ledger value is checked against its exact shape (actor, subnet label, vocabulary token, fixed sets, action-id and table-name shapes) and the estate dictionary, else `[WITHHELD]`. (c) The exporter host name must be a plain lower-case label with no estate term, or nothing starts. Tests: `SiemSchemaTest.rowKeysLeaveOnlyInAllowListedShapesOtherwisePseudonymised` (account, e-mail, host, IPv4 and IPv6 addresses, an identifier, an estate term) and `everyOtherValueMustMatchItsShapeAndHoldNoEstateTerm`; `SiemTransportTest.withoutThePrivacyKeyOrTheDictionaryNoExporterStarts` (host name case). |
| D-3 (P1) | **Fixed.** `SiemExportService.start` refuses to start any exporter without the privacy key or the estate dictionary. Health shows `DOWN` with "the privacy key or the estate dictionary is missing; nothing is exported". Test: `withoutThePrivacyKeyOrTheDictionaryNoExporterStarts` (each case separately; the receiver accepts no connection). |
| D-4 (P1) | **Fixed.** (a) The backlog (committed rows beyond the watermark, including rows held behind the xmin) is counted by the reader on every idle round, and at most every 30 s while a large backlog drains. It is shown on Health and as `rwsafe_siem_backlog_rows`. (b) The reader's and the sender's failure states are separate (`readFailure`, `sendFailure`, `rwsafe_siem_failing{thread}`); the sender's state clears only after delivery and the watermark save both succeed. (c) **Open:** the 9400 metrics listener is not served yet; `SiemExportService.prometheus()` renders the text. It is listed in CURRENT_STATE "Not done". Tests: `SiemExporterTest.aStalledDestinationDefersReadingDropsNothingAndNeverBlocksIngestion` (backlog counted and drained), `failedDeliveriesBackOffExponentiallyAndRetryTheSameBatch` (sender failure without a reader failure), `SiemTransportTest.aRunningExportShowsItsBacklogOnHealthAndInMetrics`. |
| D-5 (P1) | **Fixed.** LEEF values escape `\` and `=` with a backslash, as CEF does. Whether QRadar un-escapes them stays UNVERIFIED until one test event per format is sent. The product version in CEF and LEEF headers, and the HEC `host` and `index`, pass through `SiemText.clean`. Tests: `SiemFormatsTest.leefValuesCannotSplitOnTabsAndTheHeaderIsEscaped`, `everyHeaderAndEnvelopeFieldIsCleaned`. |
| D-6 (P1) | **Fixed as decided (Q-SIEM-1).** Ledger rows always export from the first one; `latest` applies to verdict events only. Creating a destination's watermark happens in a transaction under the audit context `system:siem-export` / `siem_export.start` / `START_FROM_LATEST` or `START_FROM_EARLIEST`. That makes the start a ledger row (V7 trigger on insert), exported like every other row. The number of skipped verdict events is stored with the watermark (`skipped_at_start`), counted in `rwsafe_siem_events_skipped_at_start_total`, logged and shown on Health. Tests: `SiemExporterTest.aLatestStartSkipsVerdictEventsOnlyAndRecordsTheSkip`, `SiemExportStoreTest.theWatermarkIsCreatedOnceUnderTheLedgerAndThenMoves`. |
| D-7 (P2) | **Fixed.** Control strings (OSC, DCS, SOS, PM, APC) end within 256 characters, and control sequences within 32; otherwise only the introducer is removed and the rest stays as cleaned text. The C1 introducers 0x90, 0x98, 0x9E and 0x9F are handled like 0x9D. Test: `SiemTextTest.anUnterminatedControlStringLosesOnlyItsIntroducer`. |
| D-8 (P2) | **Fixed.** The 1 ms read-timeout probe is gone; after the handshake the TLS socket has no read timeout. Each connection has a watcher thread blocked in a read (RFC 5425 receivers send nothing). End of stream or an error marks the connection closed by the peer, and the next batch opens a new one. Closing sends `close_notify` on the TLS socket first, then closes the TCP socket, with a guard so a stalled peer cannot hold the close. The write-timeout watchdog still closes the TCP socket. Tests: `SiemTransportTest.aClosedConnectionIsDetectedAndReplacedBeforeTheNextBatch`, `aReceiverThatStopsDrainingTimesOutInsteadOfHangingTheSender`. |
| D-9 (P2) | **Fixed.** (a) The queue holds at least two pages (`Settings` refuses less), and the reader reads one page per stream per round only when both fit, so neither stream starves. (b) `HecSink` reads the token before it builds the HTTP client. (c) The sender treats a failure seen while stopping as a stop, not a failure, and keeps the interrupt flag; the reader's pause keeps it too. Tests: `SiemExporterTest.theQueueHoldsAPageOfEachStream`, `aRestartResumesFromThePersistedWatermark`. |
| Q-SIEM-1 | **Accepted as recommended:** see D-6. |
| Q-SIEM-2 | **Both sinks stay supported.** `LOCAL_RUN.md` "SIEM export" and the `SiemExportService` Javadoc state that a deployment relying on the SIEM copy of the audit ledger uses HEC, alone or beside syslog. A syslog batch flushed on a connection the receiver then closed is counted as possibly lost (`SiemSink.possiblyLostBatches`, `rwsafe_siem_batches_possibly_lost_total`, the Health detail). Test: `aClosedConnectionIsDetectedAndReplacedBeforeTheNextBatch` (one batch counted, then the open connection is reused). |
